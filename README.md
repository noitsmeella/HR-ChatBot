# HR 챗봇 프로토타입

사내 인사 제도 문의에 답하는 **검색 전용(retrieval-only) HR 챗봇**입니다.
답변을 생성하지 않고, 사람이 작성·검수한 Q&A에서 가장 가까운 항목을 찾아 근거 규정과 함께 반환합니다.
질문 매칭은 로컬에서 실행되며, 직원 정보나 질문 내용을 외부 서비스로 보내지 않습니다.
외부와 통신하는 경로는 임베딩 모델 최초 다운로드와 법령 개정 점검(국가법령정보센터 Open API, 선택)뿐입니다.

> **프로젝트 배경**
> 대학생 대외활동 프로그램에서 기업의 HR 업무를 주제로 진행한 프로젝트입니다. 실제 회사에서 운영하거나 사용하는 챗봇이 아니며, 추후 기업에서 아이디어를 채택할 수는 있습니다.

> **공개 범위 안내**
> 이 저장소에는 **v1.0 ~ v4.0** 까지만 공개되어 있습니다(v4.0에는 법령 뉴스레터 연동 포함). 공개된 버전의 직원·휴가·휴직 데이터와 복지제도는 사내 데이터를 받기 전에 임의로 설정한 **가상 데이터**이며([data/README.md](data/README.md)), v4.0은 분류 구조의 일부만 남기고 FAQ를 내용 없는 예시 항목으로 대체했습니다.
> v5.0부터는 프로그램에서 제공받은 기업의 사내 자료(제도 문서)를 지식 소스로 사용했으며, 외부 반출 금지 조건에 따라 코드와 데이터를 공개하지 않습니다.
> 대신 아래 [이후 버전](#이후-버전-비공개)에 적용한 기법·설계와 평가 지표를 설명합니다.

### v1.0 — 기본 구조
- Streamlit 웹앱, 사번 로그인 후 직원/담당자 화면 분기
- 연차·복리후생·급여·기타 4개 카테고리, Q&A 8건(가상)
- 한국어 임베딩 모델(`jhgan/ko-sroberta-multitask`)이 설치돼 있으면 사용하고, 없으면 TF-IDF로 대체
- 유사도가 기준치 미만이면 답하지 않고 미답변 질문으로 기록해 담당자에게 전달

### v2.0 — 보안과 데이터 기준
- 타인 정보 조회 차단 4중 방어(구조적 차단 / 세션 기반 조회 / 질문 필터 / 감사 로그)
- 사내규정과 현행 법령의 관계유형 코딩: L1 법정의무, L2 법정기준 상회, L3 회사 자체 제도
- L3 제도는 답변에 "법정 제도가 아닌 회사 자체 제도"임을 명시
- 데이터 구축 기준 문서(`코드북_초안.docx`)와 생성 스크립트(`make_codebook.js`)
- 오답을 줄이기 위해 TF-IDF 기준치를 0.25에서 0.4로 상향

### v3.0 — 담당자 업무 자동화
- 대시보드: 이달의 연차·휴가 신청자, 휴직 현황, 올해 휴직자 비율, 성별×휴직종류 차트
- `report.py`: 주간 휴직·휴가 현황, 월간 휴직 통계를 xlsx로 생성(이메일 발송 스텁 포함)
- `law_tracker.py`: 국가법령정보센터 Open API로 법령 개정 점검(키 미설정 시 예시 데이터)

### v4.0 — 탐색 구조 개편
- 카테고리 4개를 중분류 → 소분류(제도명) → FAQ의 3단계 탐색 구조로 재구성
- 공개 저장소에는 분류 구조의 일부(중분류 3개, 소분류 18개)만 남김. 시연 버전에는 회사 자체 제도를 포함한 전체 분류가 있었음
- FAQ는 소분류마다 내용 없는 예시 항목 1건만 포함(실제 FAQ 미포함)
- 소분류 진입 시 FAQ를 버튼으로 표시하고, 문장형 질문은 선택한 소분류 안에서 먼저 찾은 뒤 없으면 전체에서 폴백 검색(다른 분류에서 찾으면 출처 표시)
- 분류·FAQ를 코드 한 곳(`build_qa_data.py`)에서 관리해 `qa_data.json`을 생성
- FAQ 증가에 맞춰 TF-IDF 기준치를 0.4에서 0.5로 상향
- **법령 업데이트 탭**: 별도로 구현한 법령 뉴스레터(law_newsletter)가 만든 `change_report.json`을 담당자 화면에 읽기 전용으로 표시(점검 법령 수, 변경 조문 전후 비교, HR 체크포인트). `LAW_NEWSLETTER_PATH` 미설정 시 내부 예시 데이터 사용

## 이후 버전 (비공개)

v5.0부터는 기업의 사내 자료를 사용하므로 코드와 데이터는 공개하지 않습니다. 아래는 적용한 기법과 설계, 그리고 프로젝트 평가 표본에서 측정한 지표입니다.

### v5.0 — 문서 기반 데이터 파이프라인
- 하드코딩된 Q&A 대신, 표준 양식으로 작성된 제도 문서(Markdown)를 파싱해 Q&A 데이터를 자동 생성
  - 문서 메타데이터에서 중분류·소분류를 파생하므로 분류 체계를 코드에 하드코딩하지 않음
  - 문서의 FAQ 표에서 질문·답변을 추출하며, 답변 문장은 재작성하지 않고 원문 그대로 사용
  - 문서의 근거 규정 섹션에서 규정 조항과 관련 법령을 추출해 답변과 함께 표시
- **노출 보류 로직**: 법정기준 미달이 의심되거나(L4) 근거가 확인되지 않은(`verified=false`) 항목은 검색 대상에서 제외하고 담당자 화면에만 표시
  - "법정 제도"로 분류됐는데 근거 규정에 법령 조항이 없는 문서를 빌드 단계에서 자동 검출해 보류
- 보안 필터를 하나의 모듈로 통합해 앱과 테스트가 같은 코드를 사용

### v6.0 — 권한·개인정보·데이터 품질
- **권한 설계**
  - 직원 정보 접근 권한을 역할별로 나누고, 타인 정보 접근 판정은 한 함수에서만 수행
  - 열람 권한이 없는 FAQ는 화면에서 가리는 대신 해당 세션의 **검색 인덱스에서 아예 제외**
  - 비밀번호 해시 검증, 로그인 잠금
- **개인정보 처리 설계**
  - 대화 기록은 보존기간이 지나면 자동 파기하고, 미답변 기록·보안 로그에도 같은 원칙 적용
  - 본인 기록 조회와 삭제 요청 기능, 최초 사용 시 동의 절차
  - 답변 평가(👍/👎)는 익명 저장, 통계 리포트에는 질문 원문을 넣지 않음
- **데이터 품질 관리**
  - 검수 결과를 별도 파일로 관리해 문서를 다시 빌드해도 검수 내용이 유지되도록 함. 미확정 내용이 남은 답변은 자동 보류
  - 유사 질문(패러프레이즈)을 보강하고, 원문 복사·빈 문장·FAQ 간 중복을 자동 검사
  - 배포 전 사전 점검(`preflight`)에서 데이터 오류를 차단
- **검색**: 한국어 임베딩을 기본 백엔드로 사용하고, 모델을 불러오지 못하면 TF-IDF로 폴백
- **화면**: 채팅형 UI, 상황을 고르면 관련 제도를 모아 보여 주는 "상황별 제도 찾기"

### v7.0 — 2단 응답 + gap 게이트
원칙은 그대로입니다. 답변을 생성하지 않고, 되묻기도 FAQ 원문 질문을 보여 줄 뿐 새 문장을 만들지 않습니다.

- **2단 응답 + gap 게이트**: 단일 임계값 대신 아래 순서로 판정
  1. 1등 점수가 자동 답변 기준 이상**이고** 1등과 2등의 점수 차가 gap 기준 이상 → 자동 답변 + 근거
  2. 조건 미달이고 후보 기준 이상의 항목이 있음 → "혹시 이 중에 있나요?" 후보 최대 3개
  3. 후보도 없음 → 미답변 큐 → 담당자 답변
  - 절대 점수만 보면 1등과 2등이 사실상 동점일 때도 하나를 자신 있게 고릅니다. 이 구간에서는 정답이 2·3등에 있는 경우가 많아, 되묻기로 돌리면 오답을 줄일 수 있습니다.
- **미답변 루프**: 담당자 답변을 질문자가 본인 메뉴에서 확인(세션 기준 조회). 담당자 답변은 FAQ에 자동 반영하지 않고 문서 수정 → 재빌드로만 등록
- **상시 입력창**: 분류를 고르지 않아도 바로 질문 가능. 모든 질문이 같은 경로를 지나 보안 필터가 동일하게 적용됨
- **폴백 가시화**: 임베딩 대신 TF-IDF로 동작하면 화면과 사전 점검에서 경고
- **평가 체계 설계**
  - 채점 단위를 소분류가 아닌 **FAQ 항목 단위**로 엄격하게 설정
  - "제도 선택 후 검색"과 "전체 검색" 두 조건을 나란히 측정
  - 결과를 정답 / 후보 안에 정답 / 미해결 / **자신있는 오답**(자동 답변인데 틀림)으로 나눠 집계
  - 홀드아웃: FAQ마다 유사 질문 일부를 인덱스에서 빼고 질의로 사용해, 사람의 판단 없이 정답이 정해지는 평가 표본 구성
  - 범위 밖 질문(데이터 없음 / 개인 판정 요구 / 타인 정보 / 보류 항목)을 유형별로 측정
  - 자동 답변 기준 × 마진 × gap 조합을 격자로 비교해 임계값 결정

### v7.5 — 독립 재측정과 한계 분석
v7.0 코드를 수정하지 않은 사본에서 다시 측정하고, 임계값 튜닝에 쓴 표본은 근거에서 제외했습니다.

> 아래 수치는 **프로젝트의 제한된 평가 표본에서** 측정한 값이며, 실제 운영 환경의 성능이 아닙니다. 평가 질문은 팀이 직접 만들었고, 자유질문 세트의 정답 배정은 기업 담당자 검수를 거치지 않았습니다.

**측정 조건**: 분류 선택 없이 전체 검색, 임베딩 백엔드, gap 게이트 전(gap 0)과 v7.0(gap 0.08) 비교

| 표본 | 해결률 | 자신있는 오답률 | 자동 답변 비율 |
|---|---|---|---|
| 홀드아웃 슬라이스 A (n=386) | 78.8% → **93.8%** | 21.0% → **2.9%** | 93.8% → 39.9% |
| 홀드아웃 슬라이스 B (n=386) | 77.5% → **93.8%** | 21.8% → **1.6%** | 93.0% → 35.8% |
| 자유질문 세트 (n=30) | 70.0% → **83.3%** | 26.7% → **3.3%** | 53.3% → 10.0% |

- **해결률** = 자동 답변이 정답인 경우 + 되묻기 후보 3개 안에 정답이 있는 경우
- **자신있는 오답률** = 자동으로 답했는데 정답이 아닌 경우
- 홀드아웃은 FAQ마다 유사 질문 2개를 인덱스에서 빼고 질의로 쓴 표본입니다. 슬라이스 A·B는 서로 겹치지 않습니다.

**범위 밖 질문 (자동 답변 건수, 서로 다른 두 세트에서 동일한 결과)**

| 유형 | 세트당 질문 수 | gap 0 | v7.0 |
|---|---|---|---|
| 개인 판정이 필요한 질문 | 6 | 5건 자동 답변 | **0건** (6건 모두 되묻기) |
| 보류 항목 원질문 | 4 | 2건 자동 답변 | **0건** (4건 모두 되묻기) |
| 타인 정보 조회 | 4 | 0건 (필터에서 4건 차단) | 0건 (필터에서 4건 차단) |
| 데이터에 없는 주제 | 8 | A세트 1건 / B세트 0건 | A세트 1건 / B세트 0건 |

**백엔드 비교 (홀드아웃 슬라이스 A, 전체 검색, v7.0 설정)**: 해결률 임베딩 93.8% / TF-IDF 70.2%. TF-IDF 폴백은 정상 운영이 아닌 장애 상태로 간주합니다.

**해석할 때 주의할 점**
- gap 게이트의 대가는 자동 답변 비율 감소입니다(위 표 마지막 열). 해결률은 **직원이 후보 버튼을 누른다고 가정한 상한값**이며, 되묻기 수락률은 측정하지 않았습니다.
- 자유질문 세트는 30건이라 1건이 3.3%p에 해당합니다.
- 데이터에 없는 주제는 gap 게이트로도 막히지 않는 경우가 있습니다(A세트 1건). 임계값이 아니라 데이터를 채워야 해결됩니다.
- 보류 항목 질문은 자동 답변은 없어졌지만, 같은 제도의 다른 FAQ가 후보로 뜹니다. 해결책은 보류 답변 확정입니다.
- 멀티턴 맥락은 지원하지 않습니다.

### final — 데이터 보강과 다음 측정 준비 (측정 전)
검색 코드와 임계값은 v7.0 그대로이며, 아래 변경의 효과는 아직 측정하지 않았습니다.
- **입구 FAQ 보강**: 예외 상황 FAQ만 있고 "이 제도가 무엇이고 누가 쓰나"에 답하는 대표 FAQ가 없던 제도에 입구 FAQ 추가
- **유형별 평가세트 (파일럿)**: 쉬움 / 모호함 / 혼동 유도 / 범위 밖 유형을 섞고 유형마다 성공 기준을 다르게 정해 **따로 집계**. 하나의 평균으로 합치면 gap을 올렸을 때 좋아지는 유형과 나빠지는 유형이 서로 상쇄되기 때문. 구어체·줄임말·오타를 의도적으로 포함
- **보류 항목 대체 매칭 원인 진단 도구**: 보류 항목을 물었을 때 다른 FAQ가 뜨는 원인을 "누구에게 졌는가" 기준으로 정책 / 임베딩 / 복합 질문 / 메타데이터 4가지로 분류. 운영 데이터는 건드리지 않고 임시 사본에서 비교

## 보안 설계 — 타인 정보 조회 원천 차단 (4중 방어)

1. **구조적 차단**: 개인정보는 챗봇 지식(`qa_data.json`)에 아예 존재하지 않음. 챗봇은 규정·법령만 답하므로 어떤 질문에도 타인 정보가 출력될 수 없음.
2. **세션 기반 조회**: 연차·경조사비 조회는 로그인 세션의 사번으로만 수행. 조회 대상 사번을 사용자 입력으로 받지 않음 (가장 중요한 원칙).
3. **질문 필터**: 타인 사번·이름·타인 조회 표현이 포함된 질문은 매칭 전에 차단.
4. **감사 로그**: 차단된 시도는 `data/security_log.json`에 기록되어 담당자 페이지에서 확인.

필터 테스트: `python test_security.py` (9개 시나리오)

## 담당자 대시보드 + 리포트 자동화

| 작업 | 명령 | 권장 주기 |
|---|---|---|
| 주간 리포트 (휴직/휴가 현황) | `python report.py weekly` | 매주 금요일 09:00 |
| 월간 통계 (휴직자 비율, 성별×휴직종류) | `python report.py monthly` | 매월 1일 09:00 |
| 법령 개정 점검 | `python law_tracker.py` | 매일 08:00 |

리포트는 `reports/`에 xlsx로 생성됩니다. `report.py`의 `send_email()`에 SMTP 정보를 설정하면 자동 발송까지 됩니다.
법령 트래킹은 `LAW_OC_KEY` 환경변수(open.law.go.kr 무료 발급)를 설정하면 실데이터를 수집하고, 미설정 시 예시 데이터로 동작합니다.
