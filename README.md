# HR 챗봇 프로토타입

사내 인사 제도 문의에 답하는 **검색 전용(retrieval-only) HR 챗봇**입니다.
답변을 생성하지 않고, 사람이 작성·검수한 Q&A에서 가장 가까운 항목을 찾아 근거 규정과 함께 반환합니다.
외부 API를 호출하지 않고 전 과정이 로컬에서 실행되므로 개인정보·사내기밀이 외부로 나가지 않습니다.

> **공개 범위 안내**
> 이 저장소에는 **v1.0 ~ v4.0** 까지만 공개되어 있습니다(v4.0에는 법령 뉴스레터 연동 포함). 공개된 버전의 직원·휴가·휴직 데이터는 모두 **가상 데이터**이며, v4.0의 분류는 법령 근거가 있는 법정 제도만 남기고 FAQ는 내용 없는 예시 항목으로 대체했습니다.
> v5.0부터는 사내 실데이터(사내 제도 문서)를 지식 소스로 사용하여, 사내 보안 규정(외부 반출 금지)에 따라 코드와 데이터를 공개하지 않습니다.
> 대신 아래 [이후 버전](#이후-버전-비공개)에 구현 내용과 측정 결과를 설명합니다.

공개 버전(v1.0~v4.0)은 각각 커밋으로 남아 있습니다 (`git log`).

### v1.0 — 기본 구조
- Streamlit 웹앱, 사번 로그인 후 직원/담당자 화면 분기
- 연차·복리후생·급여·기타 4개 카테고리, Q&A 8건(가상)
- 한국어 임베딩 모델(`jhgan/ko-sroberta-multitask`)이 설치돼 있으면 사용하고, 없으면 TF-IDF로 대체
- 유사도가 기준치 미만이면 답하지 않고 미답변 질문으로 기록해 담당자에게 전달

### v2.0 — 보안과 데이터 기준
- 타인 정보 조회 차단 4중 방어(구조적 차단 / 세션 기반 조회 / 질문 필터 / 감사 로그)
- 사내규정과 현행 법령의 관계유형 코딩: L1 법정의무, L2 법정기준 상회, L3 회사 자체 제도
- L3 제도는 답변에 "법정 제도가 아닌 회사 자체 제도"임을 명시
- 데이터 구축 기준 문서(`코드북_초안.docx`)와 생성 스크립트(`make_codebook.js`)
- 오답을 줄이기 위해 TF-IDF 기준치를 0.25에서 0.4로 상향

### v3.0 — 담당자 업무 자동화
- 대시보드: 이달의 연차·휴가 신청자, 휴직 현황, 올해 휴직자 비율, 성별×휴직종류 차트
- `report.py`: 주간 휴직·휴가 현황, 월간 휴직 통계를 xlsx로 생성(이메일 발송 스텁 포함)
- `law_tracker.py`: 국가법령정보센터 Open API로 법령 개정 점검(키 미설정 시 예시 데이터)

### v4.0 — 탐색 구조 개편
- 카테고리 4개를 중분류 → 소분류(제도명) → FAQ의 3단계 탐색 구조로 재구성
- 공개 저장소에는 법령 근거가 있는 법정 제도만 남김: 근무제도(2) / 법정 휴가·휴직(13) / 채용·퇴직(3), 소분류 18개
- FAQ는 소분류마다 내용 없는 예시 항목 1건만 포함(실제 FAQ 미포함)
- 소분류 진입 시 FAQ를 버튼으로 표시하고, 문장형 질문은 선택한 소분류 안에서 먼저 찾은 뒤 없으면 전체에서 폴백 검색(다른 분류에서 찾으면 출처 표시)
- 분류·FAQ를 코드 한 곳(`build_qa_data.py`)에서 관리해 `qa_data.json`을 생성
- FAQ 증가에 맞춰 TF-IDF 기준치를 0.4에서 0.5로 상향
- **법령 업데이트 탭**: 별도로 구현한 법령 뉴스레터(law_newsletter)가 만든 `change_report.json`을 담당자 화면에 읽기 전용으로 표시(점검 법령 수, 변경 조문 전후 비교, HR 체크포인트). `LAW_NEWSLETTER_PATH` 미설정 시 내부 예시 데이터 사용

## 이후 버전 (비공개)

v5.0부터는 사내 데이터가 포함되어 코드를 공개하지 않습니다. 아래는 구현 방식과 측정 결과만 정리한 것입니다.

### v5.0 — 사내 실데이터 반영
- **문서 기반 데이터 파이프라인**: 하드코딩된 Q&A를 폐기하고, 표준 양식으로 작성된 사내 제도 문서(Markdown 36건)를 파싱해 Q&A 데이터를 자동 생성
  - 문서 메타데이터에서 중분류·소분류를 파생하므로 분류 체계를 코드에 하드코딩하지 않음
  - 문서의 FAQ 표에서 질문·답변을 추출하며, 답변 문장은 재작성하지 않고 원문 그대로 사용
  - 문서의 근거 규정 섹션에서 사내규정 조항과 관련 법령을 추출해 모든 답변에 함께 표시
- **노출 보류 로직**: 법정기준 미달이 의심되는 항목(L4)이나 근거가 확인되지 않은 항목(`verified=false`)은 검색 대상에서 제외하고 담당자 화면에만 건수 표시
  - "법정 제도"로 분류됐는데 근거 규정에 법령 조항이 없는 문서를 빌드 단계에서 자동 검출해 보류 처리
- **보안 필터 단일화**: 앱과 테스트가 하나의 필터 모듈을 공유
- 법령 트래킹은 챗봇에서 분리하고 외부 법령 뉴스레터 페이지 링크로 대체

### v6.0 — 권한·개인정보·데이터 품질
- **권한 모델**
  - 직원 정보 접근 레벨(일반 / 리더 / 담당자). 타인 정보 접근 판정은 한 함수에서만 하고, 담당자가 타인 대화를 열람하면 감사 로그를 남김
  - FAQ 열람 레벨(`member` / `leader` / `staff_only`). `staff_only` 항목은 화면에서 가리는 게 아니라 직원 세션의 **검색 인덱스에서 아예 제외**
  - 비밀번호 PBKDF2 해시 검증, 로그인 잠금·세션 정책
- **개인정보 처리**
  - 대화 기록을 SQLite에 저장하고 보존기간(기본 180일)이 지나면 자동 파기. 미답변 큐·보안 로그에도 같은 정책 적용
  - 최초 1회 개인정보 동의, 본인 대화 기록 조회와 삭제 요청 화면 분리
  - 👍/👎 답변 평가는 사번 없이 익명 저장. 담당자 전달은 직원이 직접 요청할 때만 사번 포함
  - 분기 리포트에는 질문 원문을 넣지 않고 주제어 집계와 표본 수만 표시
- **데이터 품질**
  - 검수 결과를 별도 오버라이드 파일로 관리해 문서를 다시 빌드해도 검수 내용이 유지되도록 함. 미확정 선택지나 빈칸이 남은 답변은 자동으로 노출 보류
  - 유사 질문(패러프레이즈) 1,554개 추가, FAQ 198건으로 정리. 원문 복사·빈 문장·FAQ 간 중복을 자동 검사
  - 배포 전 사전 점검(`preflight`)에서 제도명·원질문 중복 등을 오류로 차단
- **검색**: 한국어 임베딩 모델을 기본 백엔드로 전환하고, 모델을 불러오지 못하면 TF-IDF로 안전하게 폴백. 기존 FAQ와 별도로 작성한 자유질문 평가세트 도입
- **화면**: 채팅형 UI로 개편(반응형, 키보드 접근성), 상황을 고르면 관련 제도를 모아 보여 주는 "상황별 제도 찾기" 추가

### v7.0 — 2단 응답 + gap 게이트
원칙은 그대로입니다. 답변을 생성하지 않고, 되묻기도 FAQ 원문 질문을 그대로 보여 줄 뿐 새 문장을 만들지 않습니다.

- **2단 응답 + gap 게이트**: 단일 임계값 대신 아래 순서로 판정
  1. 1등 점수 ≥ 0.75 **이고** 1등 − 2등 ≥ 0.08 → 자동 답변 + 근거
  2. 조건 미달이고 0.55 이상 후보가 있음 → "혹시 이 중에 있나요?" 후보 최대 3개
  3. 후보도 없음 → 미답변 큐 → 담당자 답변
  - 절대 점수만 보면 1등과 2등이 사실상 동점일 때도 하나를 자신 있게 고릅니다. 이 구간에서는 정답이 2·3등에 있는 경우가 많아, 되묻기로 돌리면 해결률과 오답률이 함께 좋아집니다.
- **미답변 루프**: 담당자가 답하면 질문자가 본인 메뉴에서 확인(세션 사번으로만 조회). 담당자 답변은 FAQ에 자동 반영하지 않고 문서 수정 → 재빌드 경로로만 등록
- **상시 입력창**: 분류를 고르지 않아도 바로 질문 가능. 모든 질문이 같은 경로를 지나 보안 필터가 동일하게 적용됨
- **폴백 가시화**: 임베딩 로딩에 실패해 TF-IDF로 내려가면 화면 경고와 사전 점검 경고 표시
- **평가 체계 재설계**
  - 채점 단위를 소분류에서 **FAQ 항목 단위**로 엄격화
  - "제도 선택 후 검색"과 "전체 검색" 두 조건을 나란히 측정
  - 결과를 정답 / 후보 안에 정답 / 미해결 / **자신있는 오답**(자동 답변인데 틀림)으로 나눠 집계
  - 홀드아웃: FAQ마다 유사 질문 2개씩 인덱스에서 빼고 질의로 사용(n=386). 정답이 구성상 정해져 있어 사람의 판단이 끼지 않음. 슬라이스를 바꿔 서로 겹치지 않는 표본을 만듦
  - 범위 밖 질문(데이터 없음 / 개인 판정 요구 / 타인 정보 / 보류 항목)을 유형별로 측정
  - 임계값 27개 조합(AUTO × 마진 × gap)을 격자로 비교해 값 확정

### v7.5 — 독립 재측정과 한계 분석
v7.0 코드를 수정하지 않은 사본에서 모든 수치를 새로 측정했습니다. 임계값 튜닝에 쓴 슬라이스는 근거에서 제외했습니다.

**전체 검색 조건, 임베딩 백엔드**

| 표본 | gap 게이트 전 (해결 / 자신있는 오답) | v7.0 (해결 / 자신있는 오답) | 자동 답변 비율 |
|---|---|---|---|
| 홀드아웃 슬라이스 A (n=386) | 78.8% / 21.0% | **93.8% / 2.9%** | 93.8% → 39.9% |
| 홀드아웃 슬라이스 B (n=386) | 77.5% / 21.8% | **93.8% / 1.6%** | 93.0% → 35.8% |
| 자유질문 세트 (n=30) | 70.0% / 26.7% | **83.3% / 3.3%** | 53.3% → 10.0% |

- 해결 = 자동 정답 + 되묻기 후보 안에 정답
- 개인 판정이 필요한 질문의 자동 답변: 5건 → 0건(두 세트 모두)
- 보류 항목이 직접 노출된 경우: 모든 조건에서 0건
- 타인 정보 조회 질문: 필터에서 4/4 차단
- TF-IDF 폴백은 같은 조건에서 해결률이 23.6%p 낮아, 폴백을 정상 운영이 아닌 장애 상태로 간주

**남은 한계 (측정으로 확인했거나 아직 측정하지 못한 것)**
- gap 게이트의 대가는 자동 답변 비율 감소입니다. 위 해결률은 **직원이 후보 버튼을 누른다고 가정한 상한값**이며, 되묻기 수락률은 아직 측정하지 않았습니다.
- FAQ에 아예 없는 주제는 1등 점수가 높고 2등과도 벌어지는 경우가 있어 임계값으로 막을 수 없습니다. 데이터를 채워야만 해결됩니다.
- 보류 항목을 묻는 질문은 자동 답변은 사라졌지만, 같은 제도의 다른 FAQ가 후보로 뜨는 현상은 남아 있습니다. 해결책은 검색이 아니라 보류 답변 확정입니다.
- 자유질문 세트는 30건이라 1건이 3.3%p입니다. 정답 배정도 담당자 검수 전입니다.
- 멀티턴 맥락은 지원하지 않으며, 구어체·줄임말·오타 입력 성능은 측정하지 않았습니다.

**검증**: 자동 테스트 68건 통과, 사전 점검 오류·경고 0건

  - FAQ 문장을 재사용하지 않고 새로 작성했으며, 측정하지 못했던 구어체·줄임말·오타를 의도적으로 포함
  - 100건으로 확장 예정. 질의와 정답 배정은 AI가 작성했고 담당자 검수 전이라 아직 근거 수치로 쓰지 않음
- **보류 항목 대체 매칭 원인 진단 도구**: 보류 항목을 물었을 때 같은 제도의 다른 FAQ가 뜨는 현상을 "누구에게 졌는가" 기준으로 4가지로 분류
  - 정책 원인(검색은 맞았고 보류 정책이 정답을 뺀 것) / 임베딩 원인(같은 제도 안 문장이 구분되지 않음) / 복합 질문(질의가 두 제도에 걸침) / 메타데이터 원인(질문이 대표성을 못 가짐)
  - 운영 데이터와 매칭 코드는 건드리지 않고, 임시 사본에서 보류 항목을 포함한 인덱스와 비교

## 보안 설계 — 타인 정보 조회 원천 차단 (4중 방어)

1. **구조적 차단**: 개인정보는 챗봇 지식(`qa_data.json`)에 아예 존재하지 않음. 챗봇은 규정·법령만 답하므로 어떤 질문에도 타인 정보가 출력될 수 없음.
2. **세션 기반 조회**: 연차·경조사비 조회는 로그인 세션의 사번으로만 수행. 조회 대상 사번을 사용자 입력으로 받지 않음 (가장 중요한 원칙).
3. **질문 필터**: 타인 사번·이름·타인 조회 표현이 포함된 질문은 매칭 전에 차단.
4. **감사 로그**: 차단된 시도는 `data/security_log.json`에 기록되어 담당자 페이지에서 확인.

필터 테스트: `python test_security.py` (9개 시나리오)

## 담당자 대시보드 + 리포트 자동화

| 작업 | 명령 | 권장 주기 |
|---|---|---|
| 주간 리포트 (휴직/휴가 현황) | `python report.py weekly` | 매주 금요일 09:00 |
| 월간 통계 (휴직자 비율, 성별×휴직종류) | `python report.py monthly` | 매월 1일 09:00 |
| 법령 개정 점검 | `python law_tracker.py` | 매일 08:00 |

리포트는 `reports/`에 xlsx로 생성됩니다. `report.py`의 `send_email()`에 SMTP 정보를 설정하면 자동 발송까지 됩니다.
법령 트래킹은 `LAW_OC_KEY` 환경변수(open.law.go.kr 무료 발급)를 설정하면 실데이터를 수집하고, 미설정 시 예시 데이터로 동작합니다.

## 파일 구조

- `app.py` — Streamlit 웹앱 (로그인 → 역할 분기 → 탐색/채팅/대시보드)
- `matcher.py` — 유사도 매칭 엔진 (단독 테스트: `python matcher.py`)
- `build_qa_data.py` — 분류 체계와 FAQ 정의 → `data/qa_data.json` 생성
- `test_security.py` — 보안 필터 테스트
- `report.py` — 주간/월간 리포트 생성
- `law_tracker.py` — 법령 개정 점검
- `legal_updates_page.py`, `services/legal_update_service.py` — 법령 업데이트 탭 (law_newsletter 결과 연동)
- `data/` — 가상 직원·휴가·휴직 데이터, Q&A 데이터, 법령 트래킹 예시 데이터
- `코드북_초안.docx`, `make_codebook.js` — 데이터 구축 기준 문서와 생성 스크립트
